Callback vs Funkcja - różnica

To pytanie trochę myli poziomy - callback to nie jest odrębny byt techniczny, tylko rola, jaką funkcja pełni w danym kontekście. Każdy callback JEST funkcją, ale nie każda funkcja jest callbackiem.

Funkcja - podstawowa jednostka kodu

Funkcja (albo metoda w C#) to po prostu nazwany blok kodu, który wykonujesz bezpośrednio, kiedy go wołasz:

int Add(int a, int b) => a + b;

int result = Add(2, 3); // wywołujesz JĄ, wiesz dokładnie kiedy się wykona - teraz

Ty decydujesz, kiedy funkcja się wykona - wołasz ją i wynik masz od razu (albo, przy async, wiesz dokładnie w którym miejscu kodu jej rezultat się pojawi).

Callback - funkcja przekazana jako dane, wywołana przez KOGOŚ INNEGO

Callback to funkcja, którą przekazujesz jako parametr do innej funkcji/metody, a ta inna funkcja decyduje, kiedy (albo czy w ogóle) ją wywoła. Ty tracisz bezpośrednią kontrolę nad momentem wykonania.

public void ProcessOrder(Order order, Action<Order> onSuccess)
{
    // ... logika przetwarzania
    onSuccess(order); // TO metoda ProcessOrder decyduje kiedy (i czy) callback się wykona,
                       // nie kod, który wywołał ProcessOrder
}

// Wywołanie
ProcessOrder(myOrder, processedOrder =>
{
    Console.WriteLine($"Zamówienie {processedOrder.Id} przetworzone!"); // to jest CALLBACK
});

processedOrder => Console.WriteLine(...) to zwykła funkcja (lambda) - ale w tym kontekście pełni rolę callbacku, bo to ProcessOrder decyduje, kiedy (a może wcale, jeśli np. rzuci wyjątek wcześniej) ją odpali.

Kluczowa różnica w jednym zdaniu

Funkcja - Ty wołasz kod i kontrolujesz kiedy. Callback - przekazujesz kod komuś innemu i to on kontroluje kiedy (i czy) się wykona.

To jest różnica kontroli przepływu (inversion of control), a nie różnica techniczna w budowie samej funkcji.

Przykłady, które już widzieliśmy

1. RelayCommand - _execute przekazany do konstruktora to callback:

SaveOrderCommand = new RelayCommand(execute: _ => SaveOrder());

Ty definiujesz SaveOrder() (funkcja), ale to RelayCommand.Execute() decyduje kiedy ją wywoła - dokładnie w momencie, gdy WPF stwierdzi, że kliknięto przycisk. Nie masz nad tym bezpośredniej kontroli.

2. PropertyChanged event - handler podpięty pod event to callback:

viewModel.PropertyChanged += (sender, e) => Console.WriteLine($"Zmieniło się: {e.PropertyName}");

Twój kod (lambda) nie wykona się, dopóki ViewModelBase.SetProperty nie zawoła PropertyChanged?.Invoke(...) - czyli w zupełnie innym miejscu w czasie, poza Twoją kontrolą.

3. Task.ContinueWith / then w innych językach - klasyczny callback dla operacji asynchronicznej:

_userService.GetUserAsync("123")
    .ContinueWith(task => Console.WriteLine($"Załadowano: {task.Result.Name}"));
    // ↑ ten callback wykona się, gdy task się zakończy - w nieznanym momencie w przyszłości

4. RetryHelper.ExecuteWithRetryAsync - operation i onRetry to callbacki:

await RetryHelper.ExecuteWithRetryAsync(
    operation: () => _userService.GetUserAsync("123"), // callback - wywoła RetryHelper, może wielokrotnie
    onRetry: (ex, attempt) => _logger.LogWarning(...)   // callback - wywoła się TYLKO jeśli operacja zawiedzie
);

onRetry może się wykonać 0, 1 lub 2 razy, zależnie od tego, co się stanie wewnątrz ExecuteWithRetryAsync - Ty tego nie kontrolujesz, tylko dostarczasz "co zrobić, jeśli zajdzie taka potrzeba".

Synchroniczny vs asynchroniczny callback - rozróżnienie, o które czasem pytają

Callback nie musi być asynchroniczny - to częste błędne przekonanie:

// Synchroniczny callback - wykonuje się OD RAZU, w tym samym wątku, zanim List.ForEach zwróci sterowanie
orders.ForEach(order => Console.WriteLine(order.Id));

// Asynchroniczny callback - wykona się PÓŹNIEJ, po zakończeniu operacji I/O, może na innym wątku
await File.ReadAllTextAsync(path).ContinueWith(t => Console.WriteLine(t.Result));

W obu przypadkach to callback (bo kontrolę nad wywołaniem ma metoda, której go przekazałeś), ale różni się kiedy i na jakim wątku się wykona.

Analogia

  • Funkcja = dzwonisz do kogoś sam i czekasz na odpowiedź na linii - Ty inicjujesz i kontrolujesz rozmowę
  • Callback = zostawiasz komuś swój numer telefonu ("oddzwoń, jak będziesz miał wyniki") - nie wiesz dokładnie kiedy (albo czy w ogóle) oddzwonią, to oni decydują

Podsumowanie tabelaryczne

Funkcja (zwykłe wywołanie) Callback
Kto kontroluje moment wykonania Wywołujący Metoda, do której przekazano callback
Kiedy się wykonuje Natychmiast, w miejscu wywołania W nieznanym momencie - później, wielokrotnie, warunkowo, albo wcale
Przykład w C# Add(2, 3) Action/Func przekazany jako parametr, event handler
Relacja do delegatów Delegat może wskazywać na funkcję Callback to funkcja użyta w roli parametru - technicznie realizowana właśnie przez delegat

Krótko: każdy callback w C# jest zaimplementowany jako delegat (bo tylko przez delegat możesz "przekazać funkcję jako wartość"), ale samo słowo "callback" opisuje sposób użycia tej funkcji (przekazanie komuś, kto zdecyduje kiedy ją odpalić), a nie jej budowę techniczną.
