Znak _ w C# - wszystkie znaczenia

To dobre pytanie, bo _ w C# ma kilka zupełnie różnych zastosowań zależnie od kontekstu - i to jest częsty temat "czy naprawdę rozumiesz różnicę" na rozmowach.

1. Konwencja nazewnictwa - prywatne pola

public class OrderViewModel : ViewModelBase
{
    private readonly IOrderService _orderService; // ← prefiks _ dla private fields
    private readonly ILogger _logger;

    public OrderViewModel(IOrderService orderService)
    {
        _orderService = orderService; // odróżnia pole od parametru konstruktora
    }
}

To jest tylko konwencja stylistyczna (z oficjalnego .NET coding style, powszechnie przyjęta), nie żadna specjalna składnia języka. _orderService to zwykła nazwa identyfikatora - kompilator traktuje _ jak każdy inny znak dozwolony w nazwie zmiennej. Przydaje się głównie do odróżnienia pola klasy od parametru/zmiennej lokalnej bez potrzeby this.orderService.

2. Discard (_) - "wyrzucam tę wartość, nie interesuje mnie"

To jest prawdziwa cecha języka (od C# 7.0) - _ jako placeholder mówiący kompilatorowi "wiem, że coś tu jest, ale świadomie tego nie użyję".

a) Discard w deconstrukcji tupli

(string name, int age, string _) = GetPersonData();
// interesuje mnie name i age, trzeci element (np. email) świadomie ignoruję

var (id, _) = (order.Id, order.InternalDebugCode); // ignoruję drugi element

b) Discard w out parametrach

// Interesuje mnie tylko CZY się udało, nie interesuje mnie sama wartość
if (int.TryParse(input, out _))
{
    Console.WriteLine("To jest poprawna liczba");
}

// Kontrast - gdybym potrzebował wartości:
if (int.TryParse(input, out int parsedValue))
{
    Console.WriteLine($"Sparsowano: {parsedValue}");
}

c) Discard w pattern matching / switch expressions

To jest szczególnie częste w nowoczesnym C# (8.0+):

public string DescribeOrder(Order order) => order switch
{
    { Total: > 1000 } => "Duże zamówienie",
    { Items.Count: 0 } => "Puste zamówienie",
    _ => "Zwykłe zamówienie" // ← "default case", dosłownie "cokolwiek innego"
};

Tutaj _ oznacza "każda wartość, która nie pasuje do wcześniejszych wzorców" - odpowiednik default: w tradycyjnym switch.

d) Discard jako ignorowanie wyniku wywołania

_ = _orderService.LogAccessAsync(orderId);
// świadomie "odpalam i zapominam" (fire-and-forget),
// jawnie mówię kompilatorowi że NIE interesuje mnie zwrócony Task

To jest przydatne, żeby zagłuszyć warning kompilatora (CS4014 - "call is not awaited") w sytuacjach, gdy naprawdę świadomie nie chcesz czekać na wynik - bez _ = dostałbyś ostrzeżenie sugerujące, że pewnie zapomniałeś await.

3. _ jako parametr lambdy, którego nie używasz

Podobna idea co discard, ale w kontekście lambd - konwencja (nie wymuszona przez kompilator, ale czytelna):

// Timer callback - nie interesują mnie żadne z przekazanych argumentów
timer.Elapsed += (_, _) => RefreshData();

// W RelayCommand - parametr "object parameter" jest ignorowany
SaveOrderCommand = new RelayCommand(_ => SaveOrder());

Ciekawostka techniczna: od C# 9.0 możesz użyć wielu _ jako osobnych parametrów w tej samej lambdzie (jak w przykładzie (_, _) => ... powyżej) i kompilator to zaakceptuje jako dwa oddzielne discardy, mimo że normalnie nie możesz mieć dwóch zmiennych o tej samej nazwie w jednym zakresie.

4. Podkreślenie jako separator cyfr w literałach liczbowych (C# 7.0+)

Zupełnie inne zastosowanie - poprawia czytelność dużych liczb:

int million = 1_000_000; // czytelniejsze niż 1000000
long bigNumber = 1_000_000_000_000L;
double pi = 3.14_15_92;
int binaryFlags = 0b1010_0101_1100_0011; // przydatne przy liczbach binarnych
int hexColor = 0xFF_EC_A5;

_ jest tu czysto kosmetyczny - kompilator go ignoruje, 1_000_000 i 1000000 to dokładnie ta sama wartość. Nie ma znaczenia gdzie dokładnie stawiasz podkreślenia (nie muszą być co 3 cyfry).

Jak odróżnić, o które znaczenie chodzi w danym kodzie

Kontekst Znaczenie
private readonly IFoo _foo; Konwencja nazewnicza pola
out _ / (a, _) / _ = SomeCall() Discard - świadome zignorowanie wartości
_ => DoSomething() w lambdzie Nieużywany parametr (forma discard)
_ jako ostatnia gałąź switch Wzorzec "wszystko inne" (default)
1_000_000 Separator cyfr w literale liczbowym

Dlaczego to jest istotne praktycznie - unikanie ostrzeżeń kompilatora

Częsty scenariusz, gdzie discard faktycznie coś zmienia w jakości kodu:

// Źle - tworzysz zmienną, której nigdy nie użyjesz - kompilator/analizator to zgłosi (CS0168/IDE0059)
Dictionary<string, Order>.TryGetValue(id, out var unusedOrder);

// Dobrze - jawnie mówisz "wiem, że to jest ignorowane"
Dictionary<string, Order>.TryGetValue(id, out _);

To jest zresztą różnica, którą część analizatorów statycznych (Roslyn analyzers, ReSharper) faktycznie wymusza - out _ jest traktowane jako czystszy kod intencji niż out var ignoredVariable, bo jasno komunikuje "ta wartość jest celowo nieużywana", a nie "zapomniałem jej użyć".
